# Pythonずかん

Wikipediaのように、言葉をクリックして潜っていける、Python学習サイトです。

## フォルダの中身

| 場所 | 中身 |
| --- | --- |
| `content/*.md` | ページの原稿（ここを編集する） |
| `assets/style.css` | 見た目 |
| `assets/site.js` | 検索、ホバーの説明、たどってきた道 |
| `assets/icons/` | ブックマーク・タブのアイコン（ひよこ＋図鑑）。絵を変えるときは `tools/make_icon.py` を直して実行する |
| `build.py` | 原稿から `site/` を作るスクリプト |
| `site/` | できあがったサイト（これを公開する） |
| `build.sh` | サイトを作り直す（`./build.sh open` で作ってブラウザで開く） |
| `save.sh` | サイトを作り直して、GitHub に送る（＝公開する） |
| `comments.py` | コードの各行に自動でつける説明のルール |
| `px_cache/` | Pyxelの画面画像（同じコードなら作り直さない） |
| `requirements.txt` | ビルドに使う部品（pygments・pyxel・pillow） |

## ふだんの作業の流れ

1. `content/` の原稿を直す
2. **確かめる**：`./build.sh open`（VS Code なら `Cmd + Shift + B`）
   - サイトを作り直して、ブラウザで `site/index.html` を開きます。公開しなくても、自分のパソコンで見られます
3. **保存して公開する**：`./save.sh "何を変えたかのメモ"`
   - GitHub の `main` ブランチに送ると、GitHub Pages が自動で公開します（1〜2分）。**無料で、何回やってもOK**
   - Claude Code に「Python図鑑に反映して」と頼んでもOK

VS Code なら、「ターミナル → タスクの実行」から、保存して公開もできます。

はじめて `./build.sh` を動かすと、このフォルダ専用のPython環境（`.venv`）を作って、必要な部品（`requirements.txt`）を自動で入れます。

ビルドすると、次のことを自動でやります。

- プログラムを実際に実行して、「実行結果」を作る（結果を手で書かなくていい）
- 存在しないページへのリンクや、エラーになるコードを見つけて止まる
- 「このページにリンクしているページ」を作る
- 検索用のデータを作る

## 困ったら、前の版に戻せる

GitHub には、保存するたびの版がすべて残っています。

- 変更の一覧：GitHub のリポジトリのページで「Commits」を開く
- 公開の記録：GitHub のリポジトリのページで「Actions」を開く
- ファイルを前の版に戻す：Claude Code に「〇〇を前の版に戻して」と頼めば、Git の履歴から戻せます

## 原稿の書き方

1ファイルに、複数のページを書けます。

```
@@ variable
title: 変数
type: 考え方
chapter: 2
syntax: 名前 = 値
summary: ひとことの説明（ホバーで出る説明、検索にも使われる）
aliases: へんすう, 入れ物
--
ここから本文
```

| 書き方 | 意味 |
| --- | --- |
| `[[slug]]` | そのページへのリンク（表示は、ページのタイトル） |
| `[[slug\|表示する言葉]]` | 表示を変えたリンク |
| `` `print` `` | 文章中のコードの言葉。`print` や `if` など登録済みの言葉は、自動でリンクになる |
| `## 見出し` | 見出し（3つ以上あると、目次が自動でできる） |
| `::: point` ～ `:::` | ポイント（`stuck` つまずき、`deep` 折りたたみ、`try` 練習、`answer` 答え、`scratch` Scratchでいうと） |

### コードの書き方

````
```python in=はなこ|12
name = input("名前は？")
```
````

- ```` ```python ```` のコードは、ビルド時に実行されて、結果が自動で表示される
- `in=はなこ|12`：`input()` に入力する値（`|` で区切る）
- `error`：わざとエラーにするコード。エラーメッセージが表示される
- `norun`：実行しない（`random` など毎回結果が変わるもの）。直後に ```` ```output ```` を書くと、結果として表示される
- コードの中の `print` や `if` などは、自動でそのページへのリンクになる

## 確認テストの書き方

各ページの最後に出る「確認テスト」は、`content/quiz-*.md` に書きます。ページごとに `@@ quiz:ページのslug` で始めます。

````
@@ quiz:print
::: q
次のプログラムを実行すると、何が表示される？
```python hideout
print("点数は", 80, "点です")
```
:::
::: a
カンマで区切ると、間に空白が入って表示されます。
:::
````

- `::: q` が問題、そのあとの `::: a` が答え（「こたえを見る」を押すまで隠れる）
- `hideout` をつけたコードは、ビルド時に実行されて、**実行結果が答えの中に自動で出る**（問題文には出ない）
- 穴埋めなど実行できないコードは `norun`、エラーになるコードは `error` もつける（`python hideout error`）
- 確認テストのないページがあると、ビルドが止まる（書き忘れ防止）

## 作ってみよう（課題）の書き方

`content/task-*.md` に、ページごとに `@@ task:ページのslug` で書きます。1ページにつき、**課題は3つ**（足りないとビルドが止まる）。

````
@@ task:print
::: t
「こんにちは」と表示するプログラムを書いてみよう。
```output
こんにちは
```
:::
::: s
```python
print("こんにちは")
```
:::
````

- `::: t` が課題、`::: s` が解答例（「解答例を見る」を押すと開く）
- 課題文の ```` ```output ```` は「こう表示されればOK」の表示例。**解答例を実際に動かした結果と同じか、ビルドが自動で確かめる**
- 解答例のコードはビルド時に実行される。`input()` を使うときは `in=値|値`、`random` など結果が変わるときは `norun` と、手書きの ```` ```output ````
- `::: t` のかわりに `::: c` と書くと「★チャレンジ」（考えて組み合わせる、少しむずかしい課題）になる。3つの課題とは別に数えるので、何個足してもいい

## 変数名のルール

生徒が「Pythonの言葉」と「自分でつけた名前」を見分けやすいように、コードの中の名前は次のルールでつける（生徒向けの説明は `naming` のページ）。

| ルール | 例 |
| --- | --- |
| カタカナで知っている英語は、そのまま | `score`、`name`、`count`、`total`、`speed` |
| それ以外は、ローマ字（キーボードで打つつづり） | `nedan`、`tensuu`、`kekka`、`kion`、`shousuu` |
| リストは、最後に `_list` | `kudamono_list`、`tensuu_list`、`x_list` |
| 数学と同じ1文字の名前はOK | `x`、`y`、`i`、`n`、`a`、`b`、`dx`、`dy` |

## 命令のカタカナ読み

各ページの先頭に、`reads:` の行を書きます。ページの上に「このページの命令の読み方」の枠が出て、「命令のよみかた」ページ（`yomi.html`）にも自動で集まります。検索でも、カタカナで見つかります。

```
reads: for=フォー | in=イン | range=レンジ
```

記号は、`=` を2つ重ねます（`==` の読みは `===ダブルイコール`）。

## コードの行ごとのコメント

ふつうの ```` ```python ```` のコードには、**各行の説明コメントが自動でつきます**（`comments.py`）。書き方に決まった形がある行はルールで、特別な行は `OVERRIDE` に足します。自分で `# ...` と書いた行は、そのまま使われます。コメントをつけられない行があると、ビルドが知らせます。確認テストの問題文のコードには、コメントはつきません。

## 書き方のテンプレート図・流れ図

````
::: tpl if文の書き方
if 〔条件〕:
····〔条件が True のときの処理〕

| 〔条件〕 | 説明 |
:::

::: flow if if文の流れ
:::
````

- `::: tpl` ：〔 〕で囲んだところが「自分で入れる部分」、それ以外は「そのまま書く言葉」。`····` は、インデント1段。空行のあとの `|` の行が、凡例
- `::: flow 名前 キャプション` ：流れ図。図は `diagrams.py` にある（`if` `ifelse` `elif` `for` `while` `function` `variable` `listidx`）

## 章の組み立て

`build.py` の `CHAPTERS`（章）と `PARTS`（3つのまとまり）で決めている。章の番号（`chapter:`）は中の番号で、画面には次のように出る。

| まとまり | 画面の表示 | 中の番号 | 原稿 |
| --- | --- | --- | --- |
| Pythonの基本 | 0〜6 | 0〜6 | `00-start.md`〜`06-modules.md` |
| Pyxelでゲームを作る | P1 はじめの一歩 | 7 | `07-pyxel-1.md` ほか |
| | P2 描く・動かす | 8 | `07-pyxel-*.md` |
| | P3 作品を作る | 9 | `07-pyxel-3.md` |
| | P4 絵と音 | 10 | `07-pyxel-3.md`・`07-pyxel-4.md` |
| | P5 ゲームの技 | 11 | `07-pyxel-3.md` |
| | P6 クラスで作ろう | 12 | `08-class.md` |
| 調べる | 辞 Pyxel辞典 | 13 | `09-pyxel-ref.md` |
| | ? 道具と困ったとき | 14 | `10-tools.md` |

- P2〜P5 のまとめページ（`07-pyxel-0.md`）は、読む順番の案内だけ。確認テストと課題はなくてもよい（`GUIDE_ONLY_CHAPTERS`）
- 基本の1〜6章は、各ページに `group: まずはこれ` か `group: 必要になったら` を書く。「必要になったら」のページの上には、「最初は飛ばしてOK」と自動で出る
- 0章・辞典・道具は、確認テストだけで、課題（作ってみよう）はなくてもビルドが通る。辞典のページは、確認テストもなくてよい
- Pyxelのコードの画面画像は、`python px` と書いたコードから自動で作る（`px_cache/`）。`.pyxres` を読みこむコードは `tools/hiyoko.pyxres` を使う

## 新しい章を足す（例：Pyxel）

1. `build.py` の `CHAPTERS` に、章を1行足す（番号、ページ名、章の名前、ひとこと）
2. `assets/style.css` に、その章の色（`--ch7` と `.ch-7`）を足す
3. `content/07-pyxel.md` に、章のページ（`kind: chapter`）と、用語のページ（`chapter: 7`）を書く
4. 新しい言葉を、コードの中でもリンクにしたいときは、`build.py` の `CODE_TERMS` に足す
5. 各ページの確認テストを `content/quiz-7-pyxel.md` に、課題を `content/task-7-pyxel.md` に書く。各ページに `reads:` も書く
6. `python3 build.py`

## 公開のしくみ（GitHub Pages）

```
content/ を直す → ./save.sh → GitHub の main → GitHub Actions が site/ を公開
```

- 公開URL：https://tanoshiku-programming.github.io/python/
